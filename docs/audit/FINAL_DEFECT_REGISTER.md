## Detailed Defect Records

### DEF-001: Domain-Shift Evaluation Closure Leakage
- **Severity**: **BLOCKER**
- **Location**: `ml/experiments/runner.py` (lines 215–224 and 615)
- **Root Cause**: `collate_split()` was defined inside `run_experiments()` and referenced outer-scope closure variable `data_by_subject` (the standard benchmark dataset) instead of the passed parameter. When `collate_split(shifted_subs)` was called, it collated `SUBJ-001`..`SUBJ-010` from `data_by_subject`, which comprised the exact training ($N=43,185$) and validation ($N=10,797$) data.
- **Impact**: Evaluated the trained model on its own training set ($N=53,982$), producing an artificially inflated Macro F1 of $0.8784$ instead of true domain-shift performance ($0.4037$).
- **Correction**: Updated `collate_split` signature to `collate_split(subs, source_dict=None)` where `source_dict` defaults to `data_by_subject` but accepts `data_shifted`.
- **Regression Test**: `tests/datascience/test_synthetic_simulation_and_sql.py::test_domain_shift_evaluation_source_isolation`.
- **Verification Status**: **FIXED_AND_TESTED** (True shifted Macro F1 verified as $0.4037$ across $53,938$ windows).

### DEF-002: Circular Ground-Truth Labeling in Feature Extractor
- **Severity**: **HIGH**
- **Location**: `pipelines/features/feature_extractor.py` (lines 45–60)
- **Root Cause**: Legacy code assigned ground-truth labels using hardcoded heuristic thresholds ($RMS < 0.10 \implies REST$, etc.) whenever window labels were missing, introducing circular label leakage.
- **Impact**: Neural networks trained on these features were learning heuristic rules rather than genuine biomechanical signals.
- **Correction**: Refactored `feature_extractor.py` to prioritize latent ground truth intervals (`ground_truth_label` / `label`) derived from the semi-Markov state simulator.
- **Regression Test**: `tests/data/test_pipeline.py`.
- **Verification Status**: **FIXED_AND_TESTED**.

### DEF-003: Model Asset & Kotlin Class Name Documentation Discrepancy

- **Verification Status**: **FIXED_AND_TESTED**.

### DEF-004: Foreign Key Insertion Order Violation
- **Severity**: **MEDIUM**
- **Location**: `ml/simulation/generator.py`
- **Root Cause**: `insert_ground_truth_batch` was invoked before `insert_session` during synthetic database generation. Because `PRAGMA foreign_keys = ON;` is enforced, SQLite threw `sqlite3.IntegrityError: FOREIGN KEY constraint failed`.
- **Impact**: Database generation crashed under strict foreign key enforcement.
- **Correction**: Reordered generation workflow to persist parent `sessions` metadata records prior to child samples, windows, and ground truth intervals.
- **Regression Test**: `tests/datascience/test_synthetic_simulation_and_sql.py::test_sqlite_persistence_and_cascading_foreign_keys`.
- **Verification Status**: **FIXED_AND_TESTED**.

---

### DEF-005: Unweighted Cross-Entropy Minority Recall Suppression
- **Severity**: **MEDIUM**
- **Location**: `ml/experiments/runner.py`, `ml/experiments/scientific_audit.py`
- **Root Cause**: Nocturnal rest represents $\approx 90\%$ of windows. Unweighted cross-entropy loss penalizes majority errors 11–40 times more than restless or active errors, causing the model to predict rest on ambiguous windows.
- **Impact**: RESTLESS recall was suppressed to $\approx 31\%$, and ACTIVE recall to $\approx 44\%$.
- **Correction**: Introduced training-only balanced class weighting ($[0.37, 3.92, 14.87]$) and square-root weighting ($[0.61, 1.98, 3.86]$).
- **Verification Status**: **FIXED_AND_TESTED** (RESTLESS recall increased from $30.98\%$ to $40.29\%$; Macro F1 increased to $0.7034$).

### DEF-006: Windows SQLite File Lock on Temp Directory Cleanup
- **Severity**: **LOW**
- **Location**: `ml/data/sqlite_storage.py`
- **Root Cause**: Python's `with sqlite3.connect(...) as conn:` only commits transactions without closing the OS file descriptor. On Windows, open handles block `tempfile.TemporaryDirectory` cleanup, raising `PermissionError: [WinError 32]`.
- **Impact**: Transient test failures during automated CI fixture teardown.
- **Correction**: Implemented `session_scope()` context manager with explicit `conn.close()` inside a `finally` block.
- **Regression Test**: `tests/datascience/test_synthetic_simulation_and_sql.py`.
- **Verification Status**: **FIXED_AND_TESTED**.

---

### DEF-007: Cloud Erasure Enforcement Following Consent Revocation
- **Severity**: **MEDIUM**
- **Location**: `app/src/main/java/com/example/sleeptrackersimulator/cloud/FirebaseCloudRepository.kt`
- **Root Cause**: Need to ensure that when a user revokes cloud sync consent (`consent = false`), new telemetry uploads are strictly blocked, while a request to delete previously uploaded data (`DELETE_SESSION`) remains durable and executes when online.
- **Verification Status**: **ALREADY_CORRECT** (Verified by `CloudErasureConsentPolicyTest.kt` and `FirebaseCloudRepositoryConsentTest.kt`).

---

### DEF-008: Physical Over-the-Air BLE Radio Transmission
- **Severity**: **HIGH**
- **Location**: Android BLE GATT subsystem (`AndroidGattDeviceTransport.kt`, `VirtualGattServer.kt`)
- **Limitation**: Software unit tests verify GATT server callback pacing, notification dispatch, and state machines via mocks. However, physical 2.4 GHz RF propagation, BLE controller packet loss, and physical smartphone flashlight/vibration thermal limits cannot be verified without physical hardware devices.
- **Verification Status**: **UNVERIFIED_BY_HARDWARE** (Honestly documented as a physical hardware limitation).
