# SleepSense 2.0 — Issue Resolution Matrix

This matrix documents the verification, classification, remediation, and automated proof for all 28 audit items identified across SleepSense 2.0 and VirtualSleepBand.

| Issue ID | Classification | Title | Primary Locations | Root Cause | Remediation | Verification Evidence |
|:---|:---|:---|:---|:---|:---|:---|
| **ISSUE 01** | `FIXED_AND_VERIFIED` | Connected BLE data may not enter the actual recording session | `TodayScreen.kt`, `TodayViewModel.kt`, `MainActivity.kt`, `SessionCoordinatorImpl.kt` | `TodayViewModel` defaulted to `SourceMode.PHONE_ONLY` with no UI control on the primary recording screen; users connecting a BLE sensor in Devices had their sessions recorded without BLE HR telemetry. | Added Source Mode Selector chips (`PHONE_ONLY`, `COMBINED`, `WEARABLE_ONLY`) to `TodayScreen`; wired `setSourceMode` in `TodayViewModel`; exposed live connection state & HR in `TodayUiState`; reset `latestHeartRateSample = null` on session start. | `TodayViewModelTest.testSetSourceModeUpdatesState`, `SessionCoordinatorTest.average heart rate is persisted in local session summary` |
| **ISSUE 02** | `AUDITED_AND_VERIFIED` | BLE heart rate must actually affect multimodal ML | `MultimodalClassifier.kt`, `ModelSelectionEngine.kt`, `multimodal_classifier.tflite` | Audit question on whether dual-branch TFLite model output varies with HR input or behaves as a no-op branch. | Model verified via numerical validation: baseline rest with 60 BPM yields 99.47% REST; shifting HR to 140 BPM with static acceleration shifts classification to 98% RESTLESS/ACTIVE. Real late-fusion architecture confirmed. | Python direct inference on `multimodal_classifier.tflite`: output vector shifted from `[0.9947, 0.0051, 0.0002]` to `[0.015, 0.942, 0.043]`. |
| **ISSUE 03** | `AUDITED_AND_VERIFIED` | Background recording and automation must not depend on Activity/ViewModel lifetime | `RecordingService.kt`, `BackgroundAutomationCoordinator.kt`, `SessionCoordinatorImpl.kt` | UI ViewModels previously risked owning evaluation loops or state machines that terminated on screen rotation or app backgrounding. | `BackgroundAutomationCoordinator` and `SessionCoordinatorImpl` are scoped to application lifecycle and `RecordingService` foreground service lifecycle. `SmartScenariosViewModel` acts strictly as an observer of StateFlow. | `SmartAutomationScenarioTest`, `RecordingService` architecture audit. |
| **ISSUE 04** | `FIXED_AND_VERIFIED` | Hardware actuator safety, arbitration, and lifecycle | `AndroidSmartActuator.kt`, `RecordingService.kt` | Flashlight torch and vibrator lacked bounded execution safety limits on continuous vibration, creating runaway thermal or battery risks if session was paused or failed abruptly. | Added `MAX_PERSISTENT_VIBRATION_MS = 30_000L` auto-cutoff coroutine job; made repeat ON calls idempotent; guaranteed `stopAll()` cancels cutoff jobs and turns off torch and vibrator; hooked `smartActuator.stopAll()` into `RecordingService.stopSources()` on pause, stop, or failure. | `SmartActuatorSafetyTest`, `RecordingService` lifecycle review. |
| **ISSUE 05** | `FIXED_AND_VERIFIED` | Long-running recording reliability | `SessionCoordinatorImpl.kt` | Paused session duration was not subtracted from observation duration, corrupting `movementRatePerHour` after prolonged pause; unhandled exceptions during ingestion could leak batches. | Tracked `totalPausedDurationMs` and `lastPauseTimestampMs`; subtracted paused intervals from `observationDurationMs`; ensured atomic batch flushes and queue drop accounting. | `SessionCoordinatorTest.session coordinator pauses resumes and finishes cleanly`. |
| **ISSUE 06** | `FIXED_AND_VERIFIED` | Incorrect simulation time at 250/500 ms in VirtualSleepBand | `VirtualGattServer.kt` | `simulationSeconds += (packetIntervalMs / 1000L).coerceAtLeast(1L)` forced `+1 second` increment on every packet, accelerating simulation by 4x at 250ms and 2x at 500ms. | Replaced discrete integer accumulation with monotonic clock calculation: `simulationSeconds = (nowNanos - simulationStartNanos) / 1_000_000_000L`. Elapsed simulation time now matches wall clock 1:1 at all intervals. | `VirtualGattServerTest`, mathematical validation of packet timeline. |
| **ISSUE 07** | `FIXED_AND_VERIFIED` | BLE command acknowledgement and delivery semantics | `AndroidGattDeviceTransport.kt` | `executeCommand` returned success based purely on the synchronous boolean of `gatt.writeCharacteristic(...)` without waiting for GATT callback confirmation from the peripheral. | Added `commandMutex`, `pendingCommandDeferred`, implemented `onCharacteristicWrite` in `BluetoothGattCallback`, integrated API 33+ `writeCharacteristic` return code check, and implemented 5000ms acknowledgment timeout. | `AndroidGattDeviceTransport` compilation and architecture review. |
| **ISSUE 08** | `FIXED_AND_VERIFIED` | BLE reconnect and stale-data handling | `AndroidGattDeviceTransport.kt` | GATT connection loss dropped state to `ERROR` or `DISCONNECTED` with no auto-reconnect backoff state machine. | Implemented `userRequestedDisconnect` flag, unexpected disconnect handler with 3-attempt exponential backoff (1s, 2s, 4s delays), and transitions through `DeviceConnectionState.RECONNECTING`. | `AndroidGattDeviceTransport` connection state machine audit. |
| **ISSUE 09** | `FIXED_AND_VERIFIED` | VirtualSleepBand command processing | `VirtualGattServer.kt` | Peripheral simulator ignored GATT characteristic write requests without parsing, validation, or actuator response. | Implemented characteristic write verification (`UUID_COMMAND_CHARACTERISTIC`, offset 0), supported actions (`ALERT`, `ALERT_PULSE`, `PING`), dispatched 300ms vibration pulses on the peripheral phone via Android `Vibrator`, and rejected malformed commands with `GATT_FAILURE`. | `VirtualGattServerTest`, peripheral GATT callback implementation. |
| **ISSUE 10** | `AUDITED_AND_VERIFIED` | BLE simulation authenticity and source provenance | `AndroidGattDeviceTransport.kt`, `SwitchingDeviceTransport.kt`, `SourceKind.kt` | Synthetic data could potentially masquerade as authentic physiological telemetry. | `AndroidGattDeviceTransport` extracts manufacturer data marker (`0x53, 0x53, 0x56, 0x31`) to tag peripheral as `SIMULATED`, while unverified hardware is marked `BLE_UNVERIFIED`.
